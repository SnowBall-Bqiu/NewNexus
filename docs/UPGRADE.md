# 版本升级与回退

1. 阅读 Release 说明并校验 `SHA256SUMS`。
2. 备份数据库、主密钥和当前 Compose/环境文件。
3. 停止自动发布或确认当前作业中心无运行中 DNS/SaaS 写作业。
4. 拉取明确版本标签，避免生产直接依赖浮动 `latest`。
5. 只启动一个控制端执行版本化迁移，`/readyz` 成功后再恢复其他 PostgreSQL API 副本。
6. 检查管理员登录、TOTP、作业、Agent 协议状态、SaaS 配额、DNS 预览与通知测试。

rc.2 Agent 可以在升级窗口继续连接，控制台会标记为降级模式；完成控制端升级后逐个使用安装脚本 `--upgrade` 更新 Agent。

回退前必须恢复升级前数据库快照。不要只替换旧二进制连接已经迁移的新数据库。SQLite 和 PostgreSQL 都遵循“旧二进制 + 对应数据库快照 + 原主密钥”成组回退。
