Additional actual MySQL regression evidence:
- v1 metadata upgraded concurrently by four callers through v4, including
  generated health/time columns and all time-retention indexes.
- Pending/stale overlap appears once; kind scope, global ordering, limit,
  boolean/null/empty timestamp semantics are preserved.
- PatchMany commits each independent 250-row chunk. An external lock on the
  first row of chunk two does not prevent chunk one becoming visible or
  receiving a concurrent SetSchedule update. A changed generation in chunk
  two remains pending after the old aggregation completes.
- EXPLAIN FORMAT=JSON confirms both SELECT FOR UPDATE OF target and UPDATE
  use eq_ref on target.PRIMARY via JSON_TABLE requested IDs + STRAIGHT_JOIN.
  This avoids the unrelated next-key/range locks of large IN lists.
- PutMany retains its whole-operation transaction; SQL failure in a later
  insertion chunk rolls back prior chunks. Result ingestion atomicity is
  outside this Store change and remains separately tested.
